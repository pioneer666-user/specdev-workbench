# 实现段指引

本指引管"业务规格获批之后、动手实现"这一段：什么时候需要方案与任务文件、怎么写、怎么执行、怎么交付。
模板管"长什么样"（`assets/plan-template.md`、`assets/tasks-template.md`），本指引管"怎么写、怎么执行"。

## 1. 何时进入、何时落文件

- **进入条件**：业务规格已获作者批准，且作者明确批准了本次实现范围。标着【待裁决】的事项
  不得当作已批准规则进入实现。
- **三问是硬要求，文件不是**：任何实现开工前必须先答清——**怎么实现？影响哪里？每步验收什么？**
  ——并经作者同意。答不清说明规格或方案还不成熟，先补齐再动手。
- **按复杂度落文件**：简单功能（一两处小改、无新规则）不强制写 plan.md／tasks.md，
  在既有计划或交付报告里把三问答清即可，不为仪式增加文件。改动跨模块、影响面广、
  或作者要求留档时才落文件；落位与命名开工时与作者确认，不自行新建目录约定。
- **不默认凑齐配套文件**：调研记录、数据模型、接口契约、快速上手指南都不作为默认必交文件。
  普通设计解释写进方案相应章节；确有需要独立成文的（如接口契约变更），先说明原因、
  纳入获批范围再写。关键业务决定不落这些文件——回业务规格。

## 2. 方案（plan）怎么写

- **职责边界**：业务规格定规则（FR-xxx 是什么）；方案只解释"怎么实现、为什么这么选、影响哪里"。
  方案引用规则编号，不重新定义同名业务规则——发现规格没写清的，回规格补或标【待裁决】，
  不在方案里另立规矩。
- 方案必须答清开工三问（与 §1 同一组），对应模板：**§2.1 怎么实现**（做法与数据流，
  不贴大段代码）、**§2.3 影响哪里**（会动的文件、模块、接口，以及既有图／详情／证据
  是否需要同步——先如实列出，同步流程见 [change.md](change.md)）、**§5 每步验收什么**（验证计划总览，
  含作者亲验项）。「为什么这么选」（§2.2 候选方案与放弃理由，关键决定按
  「决定／理由／放弃的替代」留痕）继续保留为方案解释，不属于三问、不得省略。
- 技术上下文只填与本次相关的项；未定的技术前提标【待澄清】，集中问作者，不猜。
- 验证计划在方案里给总览（含作者亲验项）；逐任务的验收放任务清单。

## 3. 任务清单（tasks）怎么写

- 从**已批准**的方案拆解；每个任务必须"能做、能验"：写清做什么（含文件路径）、
  完成后拿什么证明（「验」）、依据哪条规则（「据」）。
- **约束逐字进任务**：涉及数量上限、格式、权限、时间窗等关键约束时，把规格里的约束原文
  逐字抄进任务描述，不留实现期自由裁量；除引用编号外，关键数字也照抄，不只写"按规格"。
- 编号从 T001 连续分配、一经使用不改号；默认串行执行，有依赖在条目注明——不引入并行标记
  与分工策略。
- **测试规则**：业务逻辑与缺陷修复必须带必要的相关测试；纯样式、文案、配置类改动可用
  格式检查、预览或相关单档验证。不因"先写代码后写测试"推倒重来，也不为通过而放宽检查。

## 4. 执行纪律

- 一次只做一个获批功能；只动范围内和相关文件，不顺带扩大。
- 实现中发现业务缺口（规格没说、两种做法都合理）先停下来报告，不替作者拍板。
- 同一问题累计两轮修复仍未解决即停，报告事实、已试方法与未解决点，与作者商量。
- 实现与规格、图、详情不一致时如实摆出差异交作者裁决，不改文案抹平。
- 提交只在获批分支、只含本功能相关内容；页面效果交作者本人查看验收。

## 5. 交付前自查

- [ ] 三问已答清并获作者同意（独立文件或等价表达）。
- [ ] 每个任务有「验」且逐条执行、结果如实（含失败与未验项）。
- [ ] 业务逻辑与缺陷修复带了必要测试；测试结果如实报告。
- [ ] 未重新定义规格规则；新发现的规则去了规格或已标【待裁决】。
- [ ] 影响面中需要同步的图／详情／证据已处理或已列为待办。
- [ ] 差异与未决项如实列出，无则写"无"。

自查通过后按此报告：任务完成情况（含失败与未验项）、测试命令与结果、差异与未决项（差异明细用 [evidence-review.md](evidence-review.md) §5 的六列表展开）、提交状态；页面类改动附入口与检查点。

## 6. 边界

- 本指引只管方案与任务的编写执行；实现完成后的证据补录与规格／图／详情／源码核对见
  [evidence-review.md](evidence-review.md)，保存实现版快照由作者在管理页亲手完成
  （[project-contract.md](project-contract.md) §4），已有业务的修改同步见 [change.md](change.md)。
- 不照搬 Spec Kit implement 命令的自动执行流程、扩展 hooks 与并行执行机制。
