# 成品房间样板与搭配指导

两份布局是当前包正式家具的完整布置起点，不是新房壳或自动布局器。森林对应童话底座 `room-fairy-01`，陶瓷对应写实底座 `room-ceramic-01`；风格可混搭。实际实例、坐标与父子关系以 JSON 为准，尺寸、类别、能力及承载面始终读取同包索引指向的元数据，不在这里另抄家具目录。

## 森林：暖木阅读小屋

[forest-home.json](../assets/layouts/forest-home.json) 以蜂蜜木书架、告示牌和书桌形成高低变化。入门后对侧书架和告示牌提供可辨认的重点；西侧书桌配一盏台灯，朝向屋内，留出浏览资料的位置。南侧软垫阅读椅与落地灯相邻，矮柜上的双册书和小叶盆栽呼应阅读用途。东侧独立展台上的盆栽与细颈花瓶把装饰延伸到另一角，暖白陶瓷为暖木提供轻一点的配色。

家具组合：`reading-shelf`、`welcome-board`、`work-desk`＋`work-lamp`；`reading-chair`、`reading-light`、`reading-cabinet`＋`cabinet-books`／`cabinet-plant`；`garden-stand`＋`garden-plant`／`garden-vase`。中部留白连接这些组合，不在每个空隙填家具。两盆绿植分别服务阅读角和展示角，避免全部装饰堆在一个台面。

- **精简**：先移除展台上的花瓶或一处盆栽，再按用途决定是否需要独立展台；保留工作桌与灯、主要阅读资料入口，以及阅读角的一个低家具组合。极简或明确件数要求优先，可合并告示牌／书架的资料入口；删父项前一并核对子项及已有绑定，未经授权不删资料关联。
- **扩充**：先考虑现有矮柜顶／展台的实际盘点结果和类别，围绕某个真实用途增补一处小陈列；需要更多收纳时再考虑新的落地家具。不要把两边都复制成相同的装饰组，不在工作桌上强塞盆栽或书摆。

## 陶瓷：清透的工作与陈列室

[ceramic-home.json](../assets/layouts/ceramic-home.json) 用入口侧暖白矮柜与花瓶、书摆建立陈列重点，蜂蜜木告示牌可作介绍入口。西窗旁木书桌与台灯增加暖意，南侧软垫阅读椅和落地灯组成独立阅读角；远侧书架承接资料收纳，东侧陶瓷展台只放一盆绿植，保留干净的轮廓。柜顶、桌面和展台的装饰彼此分散，不靠填满房间体现完整。

家具组合：`welcome-board`、`entry-cabinet`＋`entry-vase`／`entry-books`；`work-desk`＋`work-lamp`；`reading-chair`、`reading-light`、`reading-shelf`；`feature-stand`＋`feature-plant`。陶瓷柜台是陈列主线，木家具与奶油软垫让空间适合阅读；没有要求新增床或凑齐所有家具。

- **精简**：先减少柜顶纯装饰，或按用途取消独立展台及其子项；主要工作／阅读组合仍应完整。介绍入口可从告示牌合并到矮柜，前提是目标能力与真实资料相符，不机械保留重复用途。
- **扩充**：优先围绕入口柜顶的主题陈列，或给阅读区域补与资料用途相符的小摆件／收纳。先盘点承载面再选物品；有空面不代表任意大小都能放。保持窗边工作角和进门的可走空间，避免把房间变成同款展台阵列。

以上都是可调整思路，**不是免校验的安全坐标**。换资产、底座、增删或移动后都须按当前包重新试摆和完整检查。阅读椅仅为静态家具，不支持坐下；两类灯是固定暖亮外观，不提供实际照明或开关动作。

## 从样板到当前业务

1. 按 [Skill](../SKILL.md) 找本次加载的真实包，核包身份、公开入口及当前家具目录；读模板与候选元数据、[房间契约](room-contract.md)及[朝向／依附](orientation.md)。样板名不能代替这些前提。
2. 只在**获准新建**时选合适样板作起点。样板的 `sample-forest-home`／`sample-ceramic-home` 是示例 roomId 和 businessId，不能登记成真实业务。将 businessId 改为真实业务目录和清单 ID，给新房间确定自己的 roomId；可沿用语义清楚的实例 ID，房内仍须唯一。
3. 根据用途、已有资料与“简洁清爽／丰富温馨／你来安排”偏好做局部调整；未给感觉时安排完整、温馨、适量装饰，不追问必填件数。明确数量、极简、必选／禁用、位置要求优先。不要机械复制同一摆法，不让用户负责坐标或承载面。
4. 调整时使用 [公开试摆](placement-checker.md)、[单件落地推荐](placement-suggestions.md)与[承载面盘点／装饰推荐](surface-placement.md)。桌面依附保存父实例、真实 surfaceId 和局部偏移；当前书桌只接受 lamp，盆栽、书摆与花瓶读实际柜顶／展台能力。有限推荐无结果或暂未确认可达时沿原诊断和两轮停点报告，不读内部实现找绕行技巧。
5. 两样板的 `bindings: []` 是有意留空。读取本业务已登记资料，按用途给具备真实能力的家具补集合，例如：告示牌放介绍或索引；书架／阅读椅放实际阅读资料；矮柜／展台放某主题说明。可以让书桌成为工作指南入口；纯装饰无需绑定。资料不存在时不造业务事实，不把全部内容重复挂每件家具，名称与简介用用户能理解的文字。
6. 用同包 `dist/check-room.js <项目Git顶层> <真实业务ID> --json` 做最终完整检查，保留命令、退出码和 JSON。只认退出0、kind=checked、ok=true；检查本业务**全部登记资料**，包括没绑家具的资料。美观、行走和点击仍交作者实际验收。

例如，本业务已登记 `docs/项目简介.md`、`docs/使用指南.md` 与 `docs/主题说明.md`，可分别交 `welcome-board`、`reading-shelf`、本房矮柜；只是映射例子，不要求每个业务都有三类资料。实际绑定写原始仓根相对路径、`action: "open-document-collection"` 和 documents 数组；流程图按真实本业务 chartId 写 charts，不写 URL，也不改 business.json 加 charts。不要从某件家具的存在推断“数据库已实现”等业务状态。

**旧房调整**不重新走新建问答，不套样板整体覆盖。保全 roomId、已有实例、子项、绑定、底座和未涉及偏好；只改作者授权的目标。缺资源、身份不明、清单损坏或要求冲突沿原规则报告，不用样板覆盖来掩盖问题。

本材料只交付两套样板和使用说明。脚本／人工适配通过不证明陌生 AI 已稳定生成同等美观房间，独立陌生 AI 完整试用另验。
