# 任务清单：<业务名称>——<功能或改动名>

  用法提示（填写时可保留，交付前删除本注释块）：
  - 本模板与《实现段指引》（references/implementation.md）配套，从**已批准**的方案拆解；

  - 「<…>」是占位符，交付前必须全部替换；简单功能可以不落本文件，
    把任务列在方案或交付报告里即可（见指引 §1）。
-->

- 输入：<plan.md 路径，或"方案见 <哪里>，已获作者批准（YYYY-MM-DD）">
- 规格：<业务规格文档路径>（本次涉及：<FR-xxx 清单>）
- 分支：<获批分支名>

## 任务

<!--
  条目格式：- [ ] T001 <做什么，含文件路径>｜验：<怎么验>｜据：FR-xxx
  规则：
  1. 编号从 T001 连续分配，一经使用不改号；完成后勾选，失败不勾并注明原因。
  2. 每条必须带「验」：完成后跑什么命令／看什么结果——写不出验收动作的任务不进清单。
  3. 每条必须带「据」：引用规格编号；涉及关键约束（数量上限、格式、权限、时间窗）时，
     把规格里的约束原文逐字抄进任务描述，不留实现期自由裁量。
  4. 默认串行执行；确有依赖的在条目里注明（依赖 T00x），不标并行标记。
  5. 业务逻辑与缺陷修复的「验」必须是真实测试或可重跑的检查，不拿"看起来对了"充数。
-->

- [ ] T001 <……>｜验：<……>｜据：FR-xxx
- [ ] T002 <……>（依赖 T001）｜验：<……>｜据：FR-xxx
