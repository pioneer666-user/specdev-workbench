# 户型与坐标算术（按样板递推，不另发明户型）

五份样板在 `assets/layouts/`，与 `tests/fixtures/building-*.json` **逐字节同内容**——生成器回归与漫游连通性回归跑的就是这五份输入（含 `single` 与 9 房派生的 `tower-9`）。其中 `row`／`court`／`tower` 沿用已验收配置，`single` 与 `tower-9` 是本轮新写的样板：**漫游观感与页面验收待作者**。

| 样板 | 结构 | 屋顶 | 适用 |
|---|---|---|---|
| `single.json` | 一间房＋前庭（无走廊） | 房间一个坡顶 | 1 个业务 |
| `row.json` | 一排房＋通长走廊＋前庭 | **一个组合屋顶**盖全部房间 | 2—8 个业务（默认） |
| `court.json` | 北排＋东西厢，三面围中庭 | **按间拆开**，每间一个 | 作者指定要中庭时（4—10 个） |
| `tower.json` | 一层前廊＋二层前廊，外置直跑梯接梯台 | **只盖顶层**，顶层房间合成一个 | 两层户型的 6 间原型（3＋3） |
| `tower-9.json` | 同上，按 §四 的递推规则派生 | 同上 | 9—16 个业务（9 间：一层 5＋二层 4） |

**样板里的业务 id、房间 id、名称都是演示值**：必须逐个替换成本项目清单里的真实 `businessId`，房间 id 按归一化规则重取，`roofs[].spaceIds`、门的 `to`、入口 `spaceId` 一并跟着改。**照抄的是结构与坐标算术，不是内容。**

网格约定：米；X 向东，Z 向南，Y 向上；`rect.x`／`rect.z` 是中心；南 = +Z 方向。

## 一、通用写法（五份样板共有）

1. 先排**非房间**空间（前庭／走廊／平台），再把房间排到它们旁边——门的 `to` 才有落点。
2. 房间与它前面的走廊/前庭**贴边**：房间的南边 `z1` 正好等于走廊的北边 `z0`（差 0.1 米就既不是共边也不算重叠）。
3. 每个房间一扇门，开向它正对的那个空间，`offset` 取"该墙中心对齐处"（居中就是 0）。
4. 窗开在外墙（与门相对那一侧），`offset` 0，宽度 ≤ 边长 − 0.4。
5. 入口放在前庭**内部、离边缘 ≥ 1 米**：别贴着墙放——完整外观下墙体加人身半径会压住入口，人一进去就卡住。
6. 一层的 `elevation` 取 0，`height` 取 3.6 左右；`style` 用本户型样板同款（`single`／`row`／`tower` 是 `warm-modern`，`court` 是 `chinese-timber`）；样板的 `construction` 块照抄（不许自己声称已实现/已验收）；`defaults`／`prototype`／`wallType`／`accent` **一概不写**（样板也不写，缺省值见契约——省略等于写上同样的缺省值，**改值才会改几何**）。
7. **房间排列用"清单顺序"＝`docs/specdev/` 下业务目录名的字典序**：`row` 一族从西到东依次排（序号 `i` 从 0 到 N−1，`x` 递增），`tower` 按它分层（前 ⌈N/2⌉ 间在一层）。作者另有指定顺序（比如按重要性）时从作者，并在报告的设计表里按同一顺序列出。

## 二、`row`（一排房，默认户型）

样板值：6 间房，房宽 `W=9`、房深 `D=8`；走廊深 `C=8`、中心 `z_c=3`；前庭深 `Y=12`；边距 `M=2`；风格 `warm-modern`。

| 部位 | 写法 |
|---|---|
| 房间 i 的 x | `x_i = (i − (N−1)/2) × W`（6 间 → −22.5 … 22.5） |
| 房间的 z | `(z_c − C/2) − D/2 = −5`（房间南边＝走廊北边） |
| 走廊 | `{x: 0, z: z_c, width: N×W + 2M, depth: C}`（6 间 → 宽 58） |
| 前庭 | `{x: 0, z: (z_c + C/2) + Y/2, width: 与走廊同宽, depth: Y}`（→ z 13） |
| 组合屋顶 | `spaceIds = [全部房间]`，`gable`，`rise 1.8`，`overhang 0.35` |
| 门 | 南墙 `offset: 0`，宽 1.8，`to` 指走廊 |
| 窗 | 北墙 `offset: 0`，宽 3 |
| 入口 | 前庭内、离边 ≥ 1 米（样板 `{x: 0, z: 17}`，前庭 z∈[7,19]） |

**改 N 或改 W 时，下面是一批必改项，改完一起核对**：

1. 全部房间的 `x` 重排（`x_i` 递推）；
2. 走廊宽度 = `N×W + 4`；
3. 前庭宽度 = 走廊宽度；
4. 组合屋顶的 `spaceIds` 跟着增减；
5. 门、窗与房间一一对应（加房＝加一条房间＋一扇门＋一扇窗）；
6. 改 `W` 时核对门窗宽度上限（`≤ W − 0.4`）。

> **为什么走廊宽度是必改项**：不跟着改时诊断**可能一条都不报**——最外侧房间的南边与走廊仍有 ≥ 门宽 的共边，`DOOR_CONNECTION` 照样通过，但房间会探出走廊之外，房子看着是坏的却"校验通过"。这一项不能指望诊断兜底。

**单房改宽同理**：不是只改一条 `rect`，而是同排所有房间的 `x` 重排、走廊与前庭宽度、组合屋顶覆盖范围一起更新。

**不等宽房间（只把某一间改宽）用总宽公式**——上面的 `x_i` 只适用于所有房间同宽：

- 总宽 `T = Σ Wᵢ`；第 i 间中心 `xᵢ = −T/2 + Σ(j<i) Wⱼ + Wᵢ/2`；
- 走廊宽 = `T + 4`，前庭宽与走廊同宽；
- 门仍取 `offset: 0`（相对本房间该墙中心），门窗宽度仍受**本房间**宽度限制（≤ `Wᵢ − 0.4`）。

不等宽时若沿用等距公式（`(i − (N−1)/2) × W`），相邻房间会重叠或留缝：差 0.1 米既不是共边、也不算重叠，生成器会各建一堵墙甚至报 `SPACE_OVERLAP`。

## 三、`court`（合院，作者点选）

样板（6 间、中庭用 `corridor` 承担）：北排两间 `16×7` 在 `z=-8`；东西厢各两间 `6×7`，`x=±19`，`z=-4.5` 与 `z=2.5`；中庭 `32×11.5` 中心 `(0, 1.25)`；前庭 `32×12` 中心 `(0, 13)`；层高 3.8；风格 `chinese-timber`。

- 三面围合：**每个房间都要与中庭共边**，门开向中庭那一侧；
- 侧翼房间的门在 `east`／`west` 墙上，`offset` 要**现算**：`共边中点 − 房间该墙中心`（样板里是 ±1.75），填 0 基本必错；
- 屋顶**按间拆开**（围合形状拼不成一个完整矩形），样板 `overhang` 取 0；
- 加/减房间时，中庭与对面厢房的位置要一起挪，否则共边断掉。

## 四、`tower`（两层，9—16 个业务）

样板 6 间（一层 3＋二层 3），`tests/fixtures/building-tower-9.json` 是同一套规则的 9 间派生（一层 5＋二层 4）——**下面是随房间数联动的规则**，照它算就能派生 9—16 间，别只改样板里的房间条目。

设：一层 `Ng = ⌈N/2⌉` 间、二层 `Nu = ⌊N/2⌋` 间（按清单顺序分）；两层总宽取**同一个** `T`；房深 `D = 6`；廊深 2；层高 3.6、楼板 0.18、二层地坪 ≥ 3.6＋0.18（取 4.2）。

| 部位 | 规则 | 样板（T=16，3＋3） | 9 房派生（T=20，5＋4） |
|---|---|---|---|
| 房间宽 | 同层 `Wᵢ = T / N层`（不等宽时同层求和必须等于 `T`；全层等宽时按下方"选宽下限"取 `T`） | 5、6、5 ／ 4、8、4 | 一层 4×5；二层 5×4 |
| 房间 x | `xᵢ = −T/2 + Σ(j<i) Wⱼ + Wᵢ/2` | −5.5、0、5.5 | 一层 −8…8；二层 −7.5…7.5 |
| 房间 z | `−1 − D/2 = −4`（南边 z=−1 就是本层前廊北边） | −4 | −4 |
| 两层前廊 | `{x: 0, z: 0, width: T, depth: 2}`，**上下对齐**（同宽同位置） | 16×2 | 20×2 |
| 前庭 | `{x: 0, z: 1 + Yd/2, width: ≤T, depth: Yd}`；入口在庭内、离边 ≥ 1 米 | 8×6 在 z=4 | 10×6 在 z=4 |
| 楼梯 | 从**一层前廊东端** `(T/2, 0)` 直跑到**梯台西边** `(T/2 + L, 0)`；`L ≥ 上升高度`（取 6）；`width 1.4`；`steps ≈ 上升 / 0.19` | (8,0)→(14,0)，22 级 | (10,0)→(16,0)，22 级 |
| 梯台 | `{x: T/2 + L + 1, z: 1, width: 2, depth: 4}`（x∈[T/2+L, T/2+L+2]、z∈[−1,3]） | x=15 | x=17 |
| 回廊 | `{x: L/2, z: 2, width: T + L, depth: 2}`：西端与本层前廊西端对齐，东端顶到梯台西边 | 22×2 在 x=3 | 26×2 在 x=3 |
| 顶层屋顶 | `spaceIds = 二层全部房间`（一间也要写上），合成一个完整矩形 | 3 间 | 4 间 |
| 门 / 窗 | 每间房门开向本层前廊（南墙 `offset: 0`、宽 1.8）；窗开北墙 `offset: 0`，宽度 ≤ `Wᵢ − 0.4` | 窗 3 | 一层窗 2.4、二层窗 3 |

三条不能破的联动：

1. **两层总宽必须相同（`T`）**：屋顶只盖顶层那一排，下层房间要落在它的覆盖范围里——**下层一旦越过屋顶覆盖范围**（典型是下层比上层宽，或下层房间探出顶层那排之外）就报 `ROOF_MISSING`；两层同宽同位置时才逐间都对得上。
2. **楼梯占的是"缺口"**：楼梯投影不许压到任何平层空间（`STAIR_SPACE_INTERSECTION`），所以一层前廊只铺到 `x = T/2`、梯台从 `x = T/2 + L` 起，中间 `L` 米谁也不占；两层前廊同宽，正好让缺口只在东端出现一次。
3. **回廊必须两头接上**：它要与本层前廊共边（z=1、x 重叠 ≥ 0.9）才走得通，同时东端顶到梯台西边；少了回廊，人从梯台下来就进不了二层前廊。

**选宽下限**：全层等宽时 **`T ≥ 2.2 × N层`**（取间数多的那层，即 `T ≥ 2.2 × Ng`；16 间时一层 8 间 → `T ≥ 17.6`）。门固定 1.8 米宽、居中，两侧各要留 0.2 米墙角，房宽不足 2.2 米就报 `OPENING_SIZE`；房子排窄了有两种改法——把门改窄（最小 0.95 米）或把 `T` 放宽。窗宽另受 `Wᵢ − 0.4` 限制，窄房间要把窗一起收窄。

改房间数时按这个顺序重算：`Ng／Nu → T（两层一致，且 ≥ 2.2 × Ng）→ 每层房宽 → 房间 x 重排 → 楼梯起终点（T/2 与 T/2+L）→ 梯台与回廊的 x／z → 屋顶 spaceIds`。

**两层最容易错的三处**：只改层数不改标高（上下贯通）；把楼梯端点接到房间上（`STAIR_ENDPOINT_KIND`）；忘记给梯井留空（`STAIR_SPACE_INTERSECTION`）。

## 五、写完先自查（比诊断更早发现问题）

- 每间业务房都绑了清单里的 `businessId`，且没有一间房绑两个业务；
- 房间与走廊/前庭**贴边**（不是差一点）；
- 每扇门都落在共边上、整扇在墙段内、门窗宽度不挤墙角；
- 每个房间上方都有屋顶，组合屋顶引用的房间同层同高、并集是完整矩形；
- 入口在前庭里、离墙 ≥ 1 米；
- 加房后走廊、前庭、组合屋顶都跟着改了；
- `construction` 与 `status` 还是默认的安全值（没替作者声明实现与验收）；
- `style` 是本户型样板的风格，`defaults`／`prototype`／`wallType`／`accent` 一个都没写。
