# 新版逐段源码对照与官方提示

只适用于renderer:3.0.1的workflow。源码事实唯一保存在nodes[].sources与meta.repository；details.md不再复制路径、行号、提交、URL或运行期refId，不向官方JSON增加私有字段。旧图仍用原“（证据 编号）”规则，不借此迁移。

## 小节关联

每个节点仍写唯一的“## 节点ID”，节点总览放在小节前。有对应实现的业务解释写在“### 业务小节”内，以独立一行声明本节点来源的精确label：

```markdown
## check
【已有实现】按顺序核对报名条件，首个失败就返回，不生成记录。

### 核对开放状态与必填信息
（源码引用 资格检查顺序）
先确认报名仍开放；开放后才检查姓名和联系方式。两者任一未满足就立即拒绝，后续重复核对与生成记录不会发生。

### 识别重复报名
（源码引用 重复报名判断）
将本次联系方式与已有报名记录比较。已有同一联系方式就拒绝；这不是姓名相同的判断，也不会覆盖原记录。
```

label须非空，不含换行或中文/英文括号界符；有配对的产物保持本节点内唯一。仅裁声明标签首尾空白，其他字符必须精确相同，不按序号、文件名或相近名称猜。来源重排不影响关联；语义未变不要随意改标签，改名必须同步声明。一个小节可写多行关联多个来源，同一来源可供多个小节使用；来源只属于本节点，不跨节点匹配。

声明是结构信息，不在右侧正文重复显示。代码围栏内的示例不生效；声明不能塞在普通段落或节点背景中。没有声明的旧新版图可继续阅读，未配对小节/来源诚实显示，不强制迁移。无实现设计不要伪造来源或声明。

制作、修改、补证均核对每组代码具体支持哪条业务规则：顺序、条件、失败后果要与查证实现一致，不能复制通用文案填两侧。声明准确与源码可读不证明业务正确；发现差异报告作者，不偷改规则。改sources时核受影响说明及标签，改说明时核所引用实现事实。

随包check-chart复用页面同一解析规则，非法声明、缺标签或同节点重复标签歧义返回内容错误（退出1），diagnostics带节点/小节/标签，不吐源码正文。保留失败与两轮上限；异常立即停，不删声明或证据绕过错误。

## 官方cards

按需把有依据的“如何阅读／业务限制／注意事项”写入官方workflow.cards。无材料可省略，不强制数量；不替代节点说明/业务规格/源码关联。合法例：

```json
"cards": [
  {"dot":"cyan","title":"如何阅读报名流程","items":["从提交报名开始，资格全部通过才生成记录。","在核对资格节点选择来源，可定位对应的业务说明小节。"]},
  {"dot":"amber","title":"拒绝与边界","items":["多个条件同时不满足时，返回首先检查到的原因。","拒绝不新增记录；此虚构样例不包含名额或候补规则。"]}
]
```

字段与dot枚举按同包common.schema.json的cards定义。卡片使用官方渲染与排版；输入、生成HTML、页内适配和实际页面各阶段核对，不能仅凭JSON有字段宣称可见。不得复制作者截图中的业务事实或凭空补限制。
